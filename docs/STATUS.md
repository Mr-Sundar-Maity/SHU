# SHU v1.0 Delivery Status

This report separates implemented code from tests that still require the target
microphone, a trained wake-word model, or consented external accounts. Installed
packages and passing unit tests do not prove live hardware or account behavior.
For a dated resume checkpoint and concise phase-by-phase remaining work, see
[PROJECT_PROGRESS.md](PROJECT_PROGRESS.md).

Latest checkpoint: 2026-11-28 r18e. The latest clean-environment suite passed 794
tests in 104.82 seconds at schema v6; the current worktree passes 803 tests in
98.44 seconds. The React voice card now exposes native activity, speech pause/
resume and reviewed planning of the last voice request. Rendered controls pass
an isolated smoke with injected playback and planning callbacks; live audio
acceptance remains open. The native
Communications dialog's WhatsApp template fields now have verified logical form
and tab order, labelled fields and accessible names/descriptions. The supplied
React frontend is now the default
desktop dashboard, connected to SHU through local Qt WebChannel. Its demo data
and simulated actions are replaced by actual runtime state and native approved
actions. Settings, advanced messaging, workflow editing and recovery controls
remain available through native dialogs. Frontend TypeScript, 63 utility tests,
production build and isolated rendered stop/resume checks pass. The supplied
frontend README is unchanged. Node.js/npm and Qt Addons/WebEngine are now needed
for the full desktop setup. Qt 6.12 also requires the separate pinned
`PySide6-WebEngine==6.12.0.140` wheel; Addons alone is insufficient. Earlier
exclusion of these packages below is historical. Fresh npm installation/build,
an isolated rendered dashboard and managed Chromium launch passed on this host.
Hardware voice, provider delivery and clean-machine acceptance remain open.

The r18d pass also fixed a native-dialog ordering defect: the template fields had
been created after the body row, so they appeared below the message box and were
reached after it by Tab. They now precede the body in both layout and focus
order, hidden fields are skipped, and the body's accessible name/description
switch between "Message text" and "Template body" with the selected mode. A
headless-Chromium check of the React Communications view confirmed its template
entry point is named and activates on Enter, and that WhatsApp mode disables and
Tab-skips Subject; the React inline composer itself intentionally has no
template fields.

At r17, WhatsApp template support was complete on the coding
side: the Cloud API adapter can submit a template to the configured business
account and send an approved template with ordered body parameters; the shared
draft flow binds the rendered preview digest to the template name, language and
values; and the dashboard Communications tab can compose text or template
drafts, including template name, language, comma-separated parameters and the
placeholder body. No template was submitted or sent: the Meta access token and
business account ID remain unconfigured and no consented recipient was supplied.
Ollama, Gmail read-only OAuth and Gemini results are unchanged from r15; cloud
generation remains unaccepted. Doctor's only remaining warnings are the WhatsApp
token and custom wake-word model. See the checkpoint for publication and
exact-commit CI evidence.

## Release licensing note

The license inventory is a dependency-metadata aid, not a legal determination.
SHU currently uses Qt Core/GUI/Widgets through PySide6 Essentials. Qt documents
those modules under LGPL and GPL options, while Qt for Python also offers a
commercial distribution; the applicable route depends on how SHU will be
distributed and which obligations the owner accepts. Review the current
[Qt for Python licensing options](https://doc.qt.io/qtforpython-6/commercial/index.html),
[Qt Core license options](https://doc.qt.io/qt-6/qtcore-index.html), and
[Qt Widgets license options](https://doc.qt.io/qt-6.12/qtwidgets-index.html)
before distributing SHU. The owner's current target is personal use only, so no
public project license has been added; a license and redistribution review are
required before sharing binaries or source with others.

  Manager using the command below. Each exact recipient/message still requires
  a digest-matched send command; Meta account setup and live delivery are unverified.
  The current adapter sends text only; WhatsApp template creation/sending is not implemented.
- WhatsApp Cloud API reference: <https://developers.facebook.com/documentation/business-messaging/whatsapp/overview>
- Reusable workflow commands are documented in the README. Saving requires a fully verified completed task; replay is always explicit and uses the same allowlisted tools and per-action approvals.
- Browser reading and one-field public form preparation are available in an
  isolated Chromium context. Form preparation has no cookies, disables
  JavaScript, blocks non-GET/HEAD requests and never submits. Sign-in,
  authenticated pages and account actions are not available.
- Keep cloud fallback disabled unless the user explicitly enables it. Speech
  generation through Edge TTS sends non-sensitive text to Microsoft's service;
  SHU blocks text flagged by its sensitive-data classifier before that call.
